# Cellular modem

SolarOS exposes cellular configuration through a common modem service. Each
hardware driver translates the common profile into its own command set. The
Waveshare ESP32-S3-SIM7670G-4G V2.0 registers its SIM7670 as `modem0` on
`modem-uart` at 115200 baud.

List the registered module and inspect its SIM, LTE registration, and signal
status:

```text
modem list
modem status
```

Create and save a packet-data profile without entering AT commands:

```text
modem profile set modem0 --apn 5g.vodafone.iot --ip ipv4v6 --auth none
modem profile show modem0
```

The profile stores the APN, IP family, authentication mode, and optional
username/password in NVS. `profile show` never prints the password. PAP and
CHAP require both `--user` and `--password`; `none` and `auto` reject explicit
credentials. `auto` asks the backend to use its default authentication policy.
The SIM7670 backend currently resolves `auto` to no authentication.

Activate or deactivate the saved packet-data context:

```text
modem connect modem0
modem status modem0
modem disconnect modem0
```

`modem connect` reapplies the saved profile before activation. On SIM7670 it
configures PDP context 1, attaches packet service, and activates that context.
This confirms a modem-side data session, but it does not create a SolarOS IP
interface. PPP/CMUX and routing SolarOS sockets over the modem remain separate
work.

Remove both the stored profile and the modem-side context configuration:

```text
modem profile clear modem0
```

If a SIM is waiting for its PIN, unlock it separately:

```text
modem sim unlock 1234 modem0
```

The PIN is sent to the modem but is not stored by SolarOS. Shell commands can
remain in terminal history, so clear sensitive command history after entering
a PIN or APN password.

Raw AT access remains available for diagnostics. Quote the command as one shell
argument; the optional device name and timeout follow it:

```text
modem at "AT+CGMM"
modem at "AT+COPS?" modem0 10000
```

The command accepts only text that starts with `AT` and rejects embedded CR or
LF characters. It prints the modem response, including an `ERROR`, before it
prints the SolarOS error name.

The modem also registers a GNSS receiver with the common service. Turn it on
before requesting a fix:

```text
gnss power on modem0
gnss fix modem0 5000
gnss power off modem0
```

`gnss fix` reports latitude, longitude, altitude, and UTC when the modem has a
valid fix. The SIM7670 AT/GNSS path does not provide satellite count or
accuracy fields, so those remain zero.

The modem profile API is shared; raw AT commands and the GNSS receiver are
SIM7670-specific capabilities. Wi-Fi remains the SolarOS IP network interface
on this board.

## Quick reference

`modem list` shows registered devices and concrete drivers. `modem status
[name]` reads SIM, LTE registration, signal, and packet-context state. `modem
profile set|show|clear` manages persistent cellular settings. `modem
connect|disconnect` controls the modem-side packet context. `modem sim unlock`
enters a SIM PIN. `modem at` remains an advanced diagnostic escape hatch. Use
`gnss power on [name]`, `gnss fix [name] [timeout-ms]`, and `gnss power off
[name]` for the integrated SIM7670 GNSS receiver.
