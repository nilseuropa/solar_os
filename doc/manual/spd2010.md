# SPD2010 QSPI display

The `spd2010` expansion driver supports 412x412 panels with a four-line SPI
interface. It registers a display target for text, indexed graphics and RGB565
images. Select the `spd2010` package group; it is included in `full` on boards
with graphics, PSRAM and expansion GPIO support.

The driver owns a dedicated SPI controller. `host=1` selects SPI2 and `host=2`
selects SPI3. The controller and all signal pins must be available. `d0` through
`d3` are the four display data lines. No named SPI bus is needed.

For a panel wired to these available GPIOs on an ESP32-S3:

```text
expansion attach spd2010 screen0 host=2 sclk=12 d0=11 d1=13 d2=14 d3=15 cs=10 bl=16 pwm=1
display list
display test screen0
expansion detach screen0
```

The default clock is 20000 kHz. `clock=100..40000` selects a clock in kHz.
`rotation=0..3` sets the initial orientation. `bgr=1` selects BGR color order;
`invert=1` enables the panel's color-inversion command. Both default to 0.

Optional `bl=<gpio>` controls the backlight. It is active-high unless `active=0`
is given. `pwm=1` enables brightness control; otherwise it is switched on or off.
The driver initializes the panel and clears its image before enabling the
backlight. Power save turns off the backlight and panel output.

Optional `power=<gpio-or-controller:line>` switches panel power. It defaults to
active-high; `power_active=0` selects active-low. Optional
`reset=<gpio-or-controller:line>` drives an active-low reset. Both accept named
GPIO-expander lines. A board profile can declare this driver as its primary
display; runtime attachments register independent display targets.

Frames are presented synchronously through queued SPI DMA. The SPI driver uses
bounded internal transfer buffers; the driver has no permanent SRAM staging buffer.
Each contiguous group of changed rows uses one LCD write window.
Text changes are batched at the display refresh boundary using the same path.
Graphics reuse the display's changed-tile map, and text and scaled indexed
graphics skip RGB conversion for unchanged rows.
Unscaled RGB565 images use direct row copies in their existing LCD byte order.
Partial graphics updates preserve video pixels outside the changed tiles.
The RGB565 backing image and text buffer use PSRAM. Frame presentation preserves
pixels outside its destination rectangle unless `clear_background` is set.
Active display ownership prevents detachment. Touch input uses a separate driver.

## Touch input

The independent `spd2010-touch` driver uses I2C address `0x53` and the existing
primary display target. Select the `spd2010_touch` package group. With the
controller wired to an available named I2C bus:

```text
expansion attach spd2010-touch touch0 i2c=i2c1 addr=0x53
input test touch0
expansion detach touch0
```

Optional `irq=<gpio-or-controller:line>` is active-low. The driver polls this
line and reads reports when it is low; omit it to poll controller status directly.
An interrupt line needs an external pull-up. `reset` is an optional active-low
control line. `power` is optional and active-high unless `active=0` is given.
All three accept GPIO-expander lines, for example `irq=gpiox0:5`.

`rotation=0..3` maps native touch coordinates to the display's initial orientation;
use the same value as the panel. One absolute pointer follows the first active
contact and publishes press, move and release events. Busy and incomplete reports
preserve the current pointer state. Malformed packets are rejected, and packet
draining is bounded. Detach joins the polling worker before closing its input source.

## Quick reference

Attach `spd2010` with `host=1|2 sclk=<gpio> d0=<gpio> d1=<gpio> d2=<gpio>
d3=<gpio> cs=<gpio>`. The dedicated controller is SPI2 for host 1 or SPI3 for
host 2. Optional `bl`, `pwm`, `active`, `power`, `power_active`, `reset`,
`clock` in kHz, `rotation`, `bgr`, and `invert` configure the panel. Power and
reset accept controller-backed GPIO lines. The default panel is 412x412 RGB565
at 20 MHz. Use display ownership and graphics APIs to draw on the named target.
Attach `spd2010-touch` independently with `i2c=<bus> addr=0x53`; optional
`irq`, `reset`, `power`, `active`, and `rotation` configure input and control lines.
